# Changelog

All notable changes to the xyz17711 Python clients are documented here (this covers the whole
`xyz17711` package family -- the `xyz17711` core plus every generated `xyz17711-<service>`
package). Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Fixed

- The core `Client` now echoes the 402 challenge's `extensions` (notably `bazaar`) back unchanged in
  the signed payment payload, as x402 v2 requires. Without it a facilitator cannot catalog the
  paid resource in its Bazaar. Omitted when the challenge carries none.

## [0.1.0] - 2026-08-26

### Added

- `xyz17711_core.Client` gains automatic x402 payment: pass `x402_private_key` (+ the three other
  `x402_*` parameters, required together) to sign and pay past the free quota automatically,
  instead of only raising `PaymentRequiredError`. New `payments` extra (`eth-account`). Cumulative
  spend is tracked per wallet address, shared by every `Client` instance in the process (not reset
  per instance) -- the safe default for the idiomatic one-`Client`-per-service usage pattern.
- Every generated method now has both a sync form and an async form (the `a`-prefixed sibling,
  e.g. `aping` next to `ping`), sharing one underlying client and one wallet.
- Every generated package gains a `langchain_tools.py` module (new `langchain` extra,
  `langchain-core`) -- one `BaseToolkit` per service, one `StructuredTool` per operation (both a
  sync and an async implementation), reusing the package's own generated request models as
  `args_schema` directly.
- Standard-library logging (`logging.getLogger(__name__)`) throughout -- a debug log at the start
  of every non-trivial function, an error log immediately before every raised error.
- Every generated package gets a real, generated `tests/` suite (`test_client.py` +
  `test_langchain_tools.py` when the package has any tool) -- one sync + one async test per
  operation at both the client level and the LangChain tool level, using each model's own new
  `_dummy()` classmethod for fixtures. `xyz17711_core` gets a thorough hand-written suite (20
  tests) covering the payment port specifically (real EIP-712 signing verified against a real
  test account, spend caps -- per-instance AND cross-instance/shared-wallet -- network validation,
  wallet config validation).
- Every generated package gets its own `README.md`, generated from one shared internal template --
  editing that template updates every package's README the next time each is regenerated.
  `readme = "README.md"` added to every `pyproject.toml`. Every README also carries PyPI
  version/Python-versions/license badges, and links to this fleet's public API and its
  [x402scan](https://www.x402scan.com) listing.
- Top-level `LICENSE` (MIT) and this `README.md`.
- New service packages: `web-scraper`, `websearch`, `emoji-match`, `ip-blocklist` -- every
  freemium/x402-gated, product-facing service in the fleet now has a client (`ping`/`proxy-pool`
  already did), each with the full README/tests/LangChain treatment above.
- New `catalog` package -- the Bazaar (`find_services_by_capability`/`search`/`category`, free to
  call, no x402 gating): semantic/keyword search over the fleet's own tool catalog. A normal,
  fully generated package with the same README/tests/LangChain treatment as every other one
  above.

### Fixed

- `xyz17711[service-registry]` extra pointed at a distribution (`xyz17711-service-registry`) that
  was never actually published -- corrected to `xyz17711-catalog`, the real package name, and the
  extra itself renamed `service-registry` -> `catalog` to match the package's own directory name
  like every other extra.
- Generated docstrings (model classes, client methods) now escape backslashes and double quotes
  from the underlying OpenAPI description before embedding it in a Python docstring -- an
  unescaped description ending in `"` or `\` could otherwise produce a `SyntaxError` in the
  generated file.
- `generate.py` now handles a bare JSON Schema boolean (`true`/`false`, meaning "any value"/"no
  value") as a field's schema, not just an object -- found regenerating `web-scraper`, whose
  `get_task_status` response has `result: true`. Resolves to `Any`.

### Changed

- Distribution names renamed `17711`/`17711-<service>` -> `xyz17711`/`xyz17711-<service>` (import
  names, e.g. `xyz17711_ping`, are unaffected -- they never changed).
- `Client` no longer accepts an `owner_key` parameter -- that mechanism is an internal
  operator-only bypass, never meant for a published client library.
- Every generated module's docstring is now a real, specific description of its contents (e.g.
  `"Pydantic request/response models for ping-service."`) instead of generic "Generated by
  generate.py -- DO NOT EDIT BY HAND" boilerplate, and never bakes in the ephemeral local URL a
  package happened to be regenerated against.
- Every generated package's `Client` docstring now references that service's own real first
  method as its sync/async example, instead of a hardcoded `ping`/`aping` pair.
- Every `pyproject.toml` (core and generated) now declares `license = { text = "MIT" }` and pins a
  version floor on the dependency to the core package (`xyz17711>=0.1.0`).
- `catalog` (service-registry's read-only discovery tools) is excluded from this first public
  release -- its 3 tools are `discoverable: false` server-side, so it can't be regenerated with
  the current tooling and would otherwise ship without a README/tests/LangChain tools like every
  other package here. It stays in the internal monorepo and will be added once regenerable.
