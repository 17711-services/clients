# Changelog

All notable changes to the `@xyz17711` Node.js clients are documented here (this covers the
whole `@xyz17711` package family -- `@xyz17711/core` plus every generated
`@xyz17711/<service>` package). Format loosely follows [Keep a
Changelog](https://keepachangelog.com/).

## [Unreleased]

## [0.1.1] - 2026-10-17

First public release of the whole family (`@xyz17711/core` plus 16 service packages).

### Added

- Nine new generated clients: `@xyz17711/address-risk`, `company-check`, `company-profile`,
  `contact-finder`, `domain-security`, `extract-correct`, `sanctions-check`, `token-verdict` and
  `url-extract`.
- Package metadata on every package: `license`, `repository`, `homepage`, `bugs`, `keywords`, an
  `author` and a plain one-line description. Published archives now contain only `dist/`, the
  README and `package.json` (`files`).

### Fixed

- The core `Client` now echoes the 402 challenge's `extensions` (notably `bazaar`) back unchanged in
  the signed payment payload, as x402 v2 requires. Without it a facilitator cannot catalog the
  paid resource in its Bazaar. Omitted when the challenge carries none.

## [0.1.0] - 2026-08-26

### Added

- `@xyz17711/core`'s `Client` gains automatic x402 payment: pass `x402PrivateKey` (+ the three
  other `x402*` options, required together) to sign and pay past the free quota automatically,
  instead of only throwing `PaymentRequiredError`. EIP-712 signing via `viem`, verified
  byte-for-byte compatible with `xyz17711_core` (Python)/this platform's own Rust buyer side
  against a fixed cross-language test vector (`packages/core/test/x402.test.mjs`) -- not just
  "looks right". Cumulative spend is tracked per wallet address, shared by every `Client`
  instance in the process (not reset per instance).
- Every generated package gains a `./langchain` subpath export (e.g. `@xyz17711/ping/langchain`)
  -- one LangChain.js `tool()` per operation, grouped in a `<Service>Toolkit` class, with a Zod
  schema derived directly from the same OpenAPI-generated types the base client uses. Requires
  the optional `@langchain/core`+`zod` peer dependencies; importing a package's base client never
  requires them.
- Every generated package gets a real, generated `test/` suite (`test/index.test.mjs` +
  `test/langchain.test.mjs` when the package has any tool), using Node's own built-in
  `node:test`/`node:assert` (no extra test dependency) with `globalThis.fetch` reassigned for the
  duration of each test. `@xyz17711/core` gets a thorough hand-written suite (14 tests) covering
  the payment port specifically.
- Every generated package gets its own `README.md`, generated from one shared internal template
  -- editing that template updates every package's README the next time each is regenerated. A
  new top-level `clients/node/README.md` (the Node-family guide) is generated the same way.
- New service packages: `web-scraper`, `websearch`, `emoji-match`, `ip-blocklist` -- every
  freemium/x402-gated, product-facing service in the fleet now has a Node client, matching the
  Python side.
- New `catalog` package -- the Bazaar (`findServicesByCapability`/`search`/`category`, free to
  call, no x402 gating): semantic/keyword search over the fleet's own tool catalog. A normal,
  fully generated package with the same README/tests/LangChain treatment as every other one
  above.

### Fixed

- The generator now handles a bare JSON Schema boolean (`true`/`false`, meaning "any
  value"/"no value") as a field's schema, not just an object -- found regenerating
  `web-scraper`, whose `get_task_status` response has `result: true`. Resolves to `unknown`.
- Every address passed to `viem`'s `signTypedData` is checksummed (EIP-55) first -- `viem`
  enforces checksum casing and throws `InvalidAddressError` on a lowercase address a seller might
  legitimately return; checksumming never changes the signed digest (ABI-encodes to the same 20
  raw bytes either way), it only satisfies `viem`'s stricter input validation.
- The generated `test` npm script now globs `test/*.test.mjs` explicitly -- `node --test test/`
  (a bare directory, no glob) silently matched zero files on this platform's Node version.

### Changed

- `ClientOptions` no longer accepts an `ownerKey` parameter -- found live: an earlier revision of
  `@xyz17711/core` had one, setting the exact `X-Platform-Owner-Key` header this fleet's own
  internal operator bypass uses. That mechanism is strictly internal, never meant for a
  published client library, in any language.
- Every generated module's docstring is a real, specific description of its contents, never
  generic "Generated by generate.mjs -- DO NOT EDIT BY HAND" boilerplate.
- `catalog` (service-registry's read-only discovery tools) is excluded from this first public
  release -- its 3 tools are `discoverable: false` server-side, so it can't be regenerated with
  the current tooling and would otherwise ship without a README/tests/LangChain wrapper like
  every other package here. It stays in the internal monorepo and will be added once
  regenerable.
